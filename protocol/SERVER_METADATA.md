# Server-visible metadata — current v2 source

This describes the reviewed source, not a measurement of the running VPS or Cloudflare retention. The [Phase 1D metadata review](METADATA_PRIVACY.md) separates observers; the [audit inventory](../SECURITY_AUDIT_CURRENT.md#server-data-inventory) lists database columns. Older Phase 1C username-era reviews are historical. Ghost Cloak IDs are public locators, not an anonymity or ownership proof.

| Operation | Backend-visible metadata |
|---|---|
| Registration/challenge/recovery | Public account/device/routing and auth-key material, challenge purpose/expiry, proof result and assigned Ghost Cloak ID. Recovery is bound to the existing device-auth key; an ID alone cannot reclaim an account. |
| Directory lookup | Authenticated requester and exact queried public ID; lookup returns stable public identity material without consuming a one-time prekey. Unknown/exhausted responses use the same generic unavailable result. |
| Prekey allocation/refill | Requester and target device relation, opaque allocation ID, public bundle, retry/expiry times and bounded rate-limit events. Allocation removes a bundle once; retry with the same bound ID can return it during the response window. |
| Send/fetch/ACK | Authenticated sender/recipient routing, envelope IDs, ciphertext size, mailbox arrival/expiry, fetch/ACK timing and dedupe/receipt state. A normal ACK indicates accepted recipient-device processing, not reading or unblocking. |
| Attachments | Owner, opaque blob ID, encrypted length/digest, capability hash, quota and upload/download timing. The server does not receive attachment plaintext. |

The current backend does not have live username, display-name, local alias, contact-acceptance, block, View Once, app-lock PIN or private Signal-key columns. It does not decrypt Signal message bodies or encrypted attachment payloads. Authenticated E2EE envelopes and capabilities still carry server-visible routing, sizes and timing. The backend can infer communication relationships; no sealed sender, relay, cover traffic or traffic-shaping defense is implemented.

Production application logging uses fixed operation/result categories rather than request bodies. The configured private nginx origin disables access logs and strips visitor-IP headers before the backend, but Cloudflare sees the source IP and TLS-terminated HTTP requests. A provider/root operator can alter software or retention, and database backups may retain metadata after live-row expiry. None of these controls provide “zero metadata” or network anonymity.

Current source defaults to a seven-day undelivered mailbox expiry. Legacy UUID receipts record a 30-day logical expiry but remain retained because the old ID cannot be rejected from that timestamp alone; V3 receipts use their immutable embedded expiry and are retired after it. Pending local message requests use a separate 72-hour window from authenticated recipient commit, with time-uncertain reboot cases withheld from reveal. V008 allocation response bytes expire after 24 hours; terminal tombstones remain until 48 hours. These are logical retention rules, not guarantees of physical deletion from WAL, backups, caches or a recipient device. See [request timing](../Android/REQUEST_CLOCK_CORRECTION.md), [Q.2 allocation limits](../infrastructure/ABUSE_RESISTANCE_Q2.md) and [backup policy](../infrastructure/BACKUP_POLICY.md).

P13.3A changes receipt retention only for V3 expiring submission IDs. A worker deletes at most 128 V3 receipts per 30-second cycle after the ID's intrinsic deadline; the server rejects that old ID without a row. Legacy UUID receipts are retained conservatively and remain server-visible metadata. Deletion from the live table does not erase WAL, backups, endpoint records or metadata already observed by infrastructure. See [V009 retirement and capacity](../infrastructure/P13_3A_RECEIPT_RETIREMENT.md).
